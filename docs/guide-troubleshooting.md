# 机场节点超时或晚高峰变慢怎么办｜连接问题排查

[机场推荐首页](../README.md) · [机场测评目录](airports.md) · [内容导航](README.md)

节点超时、订阅失败和应用打不开可能来自不同环节。先定位现象，再记录环境，通常比反复重装更容易找到原因。

## 按现象分开查

| 现象 | 先检查 | 下一步 |
|---|---|---|
| 订阅更新失败 | 套餐、链接格式、官网通知 | 确认订阅是否被重置，换网络检查更新 |
| 全部节点超时 | 本地网络、客户端时间、内核版本 | 看官方故障通知，核对协议与配置 |
| 只有个别节点失败 | 当前节点状态、地区与权限 | 换有权限的其他节点，记录失败节点 |
| 能连接但某应用失败 | 规则、地区、账号与平台状态 | 分别测试普通网页与目标应用 |
| 晚高峰明显变慢 | 节点负载、本地宽带与Wi-Fi | 对比另一个节点及另一种接入网络 |
| 流量扣除异常快 | 倍率、后台更新、上下行统计 | 查看后台消耗并减少非必要传输 |

## 一次只改一个条件

先保留同一设备、应用和任务，再逐一改变节点、接入网络或时间段。多个条件同时变化，会难以判断改动与结果的关系。

## 向客服提供哪些信息

- 发生时间、所在地区、运营商和设备系统。
- 客户端名称与版本、节点名称和错误提示。
- 是所有节点失败，还是某个地区或应用异常。
- 已经做过哪些检查，以及另一个网络下是否相同。

截图去除密码、订阅凭据和二维码。不要在公开Issue中上传完整订阅配置。

## 官网入口变动与服务故障分开看

官网域名变化不直接证明节点全部失效；节点可连接也不证明后续运营稳定。保留绑定邮箱、订单和官方通知渠道，按多个证据判断，不凭单次访问失败下结论。
